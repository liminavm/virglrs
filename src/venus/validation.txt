# How each served venus command is held to the guest's input, and which still is not.
#
# A host Vulkan driver checks nothing: every valid-usage rule a command breaks is undefined
# behaviour in this process. The decoder makes a command wire-sound -- arena pointers, each array
# its own count long, handles resolved, a null handle refused where vk.xml requires an object, an
# enum refused where vk.xml does not define the value, a bitmask refused where it sets a bit vk.xml
# does not define -- and none of that says a command is valid
# Vulkan. This file says, for each served command, whether anything stands between the guest's
# values and the driver indexing or copying by them.
#
#   validated         A check refuses the values the driver would index or copy by unchecked,
#                     before the driver sees them, and a test with a sabotage entry holds it.
#   reviewed          An audit of the driver found no guest value it indexes or copies by beyond
#                     what the decoder already refuses. Reviewed against KosmicKrisp and the Mesa
#                     runtime: a host driver that trusts more is a reason to look again.
#   pending:<group>   A known hazard with no check yet. `group` is the kind of check it needs:
#                     limits (the device's limits), buffers (an offset or range against the
#                     buffer's own size), pipelines, render-passes, descriptors, images (the
#                     image's own extent, levels and layers), regions (copy, blit and resolve
#                     regions against their images), queries.
#
# `every_served_command_is_classified_for_validation` holds this file to the handlers: a command
# served without a line here fails it, so serving a command is a decision about its input too.
# Validating a command moves its line to `validated`; this section empties as that work lands.
